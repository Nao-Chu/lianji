把九张孤立的中药分类导图，串成一张可以搜索、跳转、互相对照的记忆网络。

**在线访问：** <https://nao-chu.github.io/bencao-jingwei/>

纯静态站点，无框架、无构建步骤，双击即可离线使用。

## 能做什么

### 全站搜索

- 快捷键 `Ctrl K`（macOS 为 `⌘ K`），或按 `/` 直接唤起。
- 搜索范围覆盖药名、药性标签、功效、主证、特长、所属分类与药物组。
- 结果按相关度排序：药名精确匹配 > 药名前缀 > 药名包含 > 药性标签 > 功效/主证/特长命中。
- 支持 `↑` `↓` 选择、`Enter` 打开、`Esc` 关闭。
- 点击结果会跳转到对应导图，并自动滚动、高亮那一味药。

### 深链接

每味药都有稳定的锚点，可以直接分享到具体一味药：

```
https://nao-chu.github.io/bencao-jingwei/library/清热药.html#herb-黄连
```

打开后药卡会短暂高亮，方便课堂演示或笔记引用。

### 首页索引

- 193 味药按大类分组，一页纵览。
- 可按大类筛选，也可输入关键词过滤（如「安胎」「润肠」「止呕」）。
- 每个药名都可直接跳到对应导图中的位置。

### 相关大类串联

每张导图底部按病机的上下游接上相邻大类，例如：

- 解表 → 清热 → 泻下
- 祛湿 ↔ 化痰 ↔ 补虚
- 理气 → 活血 → 补虚

不是按目录顺序，而是按「病邪往哪走、治法往哪接」组织，便于建立横向联系。

### 其他

- 顶栏提供全站九大类导航，当前页高亮。
- 响应式布局，手机、平板、桌面均可阅读。
- 支持直接用 `file://` 打开，也支持本地 HTTP 服务。

## 快速开始

### Windows（推荐）

双击 **`启动网站.bat`**：

- 自动在 `8765` 端口启动本地服务并打开浏览器；
- 同时显示局域网地址，手机连同一个 Wi-Fi 即可访问；
- 重复双击不会重复启动，只会再打开一个页面。

### 其他系统，或手动启动

```bash
python -m http.server 8000
```

然后打开 <http://127.0.0.1:8000/>。

> 也可以直接双击 `index.html`，但用 HTTP 服务访问时路径解析和行为更接近线上环境。

## 设计思路

### 分类轴

每张大类不是药名罗列，而是先给一条分类轴。例如：

- 解表药先分**发散风寒 / 发散风热**两大类，再在类下按开表、解肌、祛风、透疹、利咽等线索细分；
- 清热药按**热邪层次**推进：泻火、燥湿、解毒、凉血、退虚热；
- 温里药按**温哪里、怎么温**两条轴，分出回阳、温中、引火归元与散肝寒；
- 补虚药按**气、阳、血、阴**四类扶正，收涩药负责敛汗、敛肺、涩肠、固精。

### 数据驱动

页面骨架与内容分成两部分：

- 内容源：`library/*.html` 中的 `<section>` / `.cluster` / `<article class="card">` 结构；
- 结构化数据：`assets/herbs.js` 中的 `window.SITE`，包含页面元信息、统计、分类、相关大类以及 193 味药的字段。

顶栏、搜索、索引、相关推荐都由 `site.js` 在运行时读取 `window.SITE` 渲染，因此新增或修改药材后，只需要同步更新数据文件，交互层不用改动。

### 视觉

每个大类有一个主题色与一个「水性」字（表、热、下、湿、温、痰、气、血、补），用于顶栏、索引、相关卡片的高低对比和快速识别。

## 数据字段

`assets/herbs.js` 中的每味药大致包含：

| 字段 | 含义 |
| --- | --- |
| `n` | 药名 |
| `t` | 药性标签（如「辛温解表」） |
| `p` | 所属页面路径（如 `library/解表药.html`） |
| `s` | 页面内 section id |
| `cat` | 所属分类 |
| `g` | 所属药物组 |
| `gx` | 功效 |
| `zz` | 主证 |
| `tx` | 特长 |
| `note` | 注意或炮制 |

`window.SITE` 还包含 `pages`（每页的元信息、统计与分类轴）和 `related`（相关大类及推荐理由）。

> `assets/herbs.js` 是由导图页面抽取生成的派生文件，不建议直接手改；内容调整应以 `library/*.html` 为准，修改后运行 `python tools/build_data.py` 重建。

## 维护脚本

仓库根目录的 `tools/` 提供两段维护脚本：

| 脚本 | 用途 |
| --- | --- |
| `tools/build_data.py` | 解析 `library/*.html`，重建 `assets/herbs.js` |
| `tools/deploy_api.py` | 通过 GitHub API 发布当前提交（适用于无法直连 `github.com` 的网络，需要本机已保存 GitHub 凭据） |

```bash
python tools/build_data.py
python tools/deploy_api.py
```

前者用于内容修改后同步数据，后者仅在需要发布时执行；`deploy_api.py` 会拒绝在有未提交改动时运行。

## 部署

站点托管在 GitHub Pages，仓库为 `Nao-Chu/bencao-jingwei`，发布分支 `main`，目录为仓库根目录。

标准流程：

1. 修改 `library/`、`assets/` 或 `index.html`；
2. 提交并推送到 `main`；
3. GitHub Pages 自动重建，约 1～2 分钟后生效。

线上地址：

- 首页：<https://nao-chu.github.io/bencao-jingwei/>
- 导图示例：<https://nao-chu.github.io/bencao-jingwei/library/清热药.html>

`index.html` 必须保留在仓库根目录；`.nojekyll` 用于避免 Jekyll 忽略下划线开头的文件。
